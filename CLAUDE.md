# spec-driven-kit

This repo is the kit itself: an agentic development kit (neutral roles and workflow, generated adapters for Claude Code, Codex, OpenCode, Cursor and Gemini CLI, hooks, git-hook guards, verify engine, stacks) plus tools that set up the project side
(`<project-dir>` = `.sdkit/`, committed except its personal and generated files; plus `AGENTS.md`, the kit block in `.claude/CLAUDE.md`, and generated host files, hidden from git per clone) in other repos. It is not a consumer of the kit; nothing here is a project.

Orientation: `README.md` (overview), `docs/guide.md` (full guide), `CONTRIBUTING.md` (how to change the kit), `docs/README.md` (reading map).

## Rules for working here

- **Keep the kit generic.** No project-specific branch names, cluster names, service names or risk criteria in skills, agents, hooks or scripts.
  Those come from the consuming repo's `<project-dir>/sdkit.env` (shared), `sdkit.local.env` (personal, read after it) and `project.md` at run time.
- **Never hardcode `.claude/` for project facts.** Scripts and hooks find the project directory with the resolver (`.sdkit` with `sdkit.env`, else a pre-1.0 `.agentkit`, `.claude` or `.codex` with `project.env`); docs and skills say `<project-dir>`. `.claude/` is literal only for Claude Code's own files (`CLAUDE.md`, `settings.local.json`, copy-mode `agents/ skills/ hooks/`).
- **Never overwrite project-side files** in `bin/init.sh` (`project.md`, `sdkit.env` (it only appends new settings), `rules/`, `settings.json`), not even with `--force`.
- **Hooks are off by default**: an empty setting means exit 0 silently. A hook only blocks on a deliberate decision, never because of its own error.
  Use `hooks/lib.sh` (`jget`, `decide`). Stop hooks check `stop_hook_active`.
- **`core/roles/` is the source of truth for roles.** `agents/` and `adapters/<host>/agents/` (codex, opencode, cursor, gemini) are generated by `bin/build-adapters.sh` (per-host code in `bin/emit/`); never edit them by hand, and run the script (and commit its output) after changing a role.
- **Roles stay narrow**: independent roles (`verifier`, `reviewer`, `security-auditor`) are `read-only`; `test-writer` edits tests only; the implementer never verifies. Roles declare a cost `tier`, never a model name. Keep the verifier's
  `DOD / FINDINGS / VERIFY / VERDICT` format exact, `spec-driven-dev` depends on it.
- **Keep `SKILL.md` short.** Step detail lives in `skills/spec-driven-dev/references/` and is read only at the step that needs it (token economy). Skills must stay host-neutral: host-specific tool names go through `references/hosts.md`.
- **`spec-driven-dev` is a driver, not a reimplementation**: it calls the OpenSpec skills. Do not copy their logic into it.
- Shell scripts are bash; match the style of neighbouring files.

## When you change something

- Keep the numbers and tables in sync in one change: skill/role/hook/script counts and the settings list appear in `README.md`, `core/roles/README.md`, `docs/guide.md`
  (§2, §6, §7, §10, §15) and `docs/cheatsheet.md`.
- Version bumps go in **both** `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`, plus the version badge at the top of `README.md`.
- Docs: `README.md` short; `docs/` English; details live in `docs/guide.md` and other files link to it instead of repeating it.
- Commits follow `core/rules/git.md` (`<type>(<scope>): <description>`, imperative, ≤ 72 chars).

## Checking a change

Run the tests your change maps to (`scripts/test-select.sh run`; `tests/fast.sh` runs every test in parallel inside a Debian container (`--no-docker` to run locally) and flags one over 30 s; `tests/smoke.test.sh` is the smoke test of the deterministic scripts, hooks, run-role dry runs and init; `tests/old/` is the long pre-slimming reference, never run), `bin/build-adapters.sh --check`, `bash -n` on touched scripts, `jq .` on touched JSON, `shellcheck` if installed, and exercise hooks by piping a
sample tool-call JSON on stdin (both a case that must trigger and one that must not). For `init.sh`/`doctor.sh`, run them against a
scratch `git init` directory. See `CONTRIBUTING.md` for the commands.
